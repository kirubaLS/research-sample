On "15 to 20 questions is enough"

For a six-scale instrument, 15–20 items means 2–3 items per scale. Internal consistency at that length lands around α ≈ 0.5, which means roughly half the variance in a student's score is measurement noise — you would be giving stream advice from a coin flip, and it would not survive one sceptical parent.

36 items — six per scale — is the shortest honest design, and at a 5-point scale it takes a Class X student about eight minutes. That is still a single period activity. If you need shorter, 24 items (four per scale) is the floor I'd defend; below that, don't publish a recommendation, publish an exploration.

01

Use case 1 — the interest test site

Five student screens ending at "thank you". Everything past that point belongs to the principal.

The instrument

RIASEC / Holland Codes, six interest types: Realistic, Investigative, Artistic, Social, Enterprising, Conventional. Chosen because it is the only widely-used career-interest model with fifty years of published validation, because O*NET's item set is US-government public domain so you can adapt items freely with no licence, and because six scores map cleanly onto the four post-Class-X routes a Tamil Nadu CBSE student actually chooses between.

Design decisionChoiceReason
Item count36 — six per scaleShortest length that reaches α ≈ 0.75–0.80 per scale. Below this you are reporting noise.
Item formatActivity statement, 5-point like/dislike"Repair a bicycle brake." Free of aspiration bias — asks what they'd do, not what they'd be.
LanguageEnglish + Tamil, toggle mid-testNon-negotiable in Krishnagiri. Item text is stored per locale; the item ID and scale are language-neutral.
Reverse-keyed pairs3 pairs embeddedCatches straight-lining without adding a visible "attention check", which teenagers spot instantly.
OrderScale-interleaved, fixed seed per studentPrevents block effects; fixed seed makes a session reproducible for audit.
Presentation6 screens × 6 itemsProgress is visible, autosave points are natural, and no screen feels like a wall of text on a phone.

Data model for use case 1

                 consent_ref, created_at)          -- identity, restricted schema

item_response stores shown_at and answered_at, not just the value. Those two timestamps are the entire validity layer — you cannot add them retroactively, so they go in on day one.

02

Use case 2, pipeline A — reading the question paper

Done once per paper and amortised over forty students. That economics is why this stage can afford to be paranoid.

The CBSE detail that breaks naive implementations

CBSE papers carry internal choice — "attempt any one of Q31 or Q32". A naive sum over max_marks then exceeds the paper total and gate G1 fails on a perfectly good extraction. That's why choice_group_id is in the schema from the start: questions sharing a group contribute their marks once. Handle this on day one or you will spend Sprint 2 debugging a gate that was right all along.

05

The anti-hallucination stack

You asked for an algorithm that can't be beaten. This is the honest version of that: eight independent layers, each catching a different failure, and a measured residual that always reaches a human.

The measurement that makes the claim real

Keep a permanent audit sample: 10% of scripts re-keyed by hand, including cells the system was confident about. Publish the resulting error rate in the principal's dashboard. Without this you have a system that feels accurate; with it you have one that can prove it — and if accuracy ever drifts, you find out from the dashboard rather than from an angry parent.

06

The NCERT knowledge base — RAG or tree?

Both, in a specific order. This is the same answer as before, now stated for the CBSE Class X Maths corpus specifically.

The NCERT book is not an unstructured corpus and must not be treated as one. It already carries the hierarchy the product needs — Book → Chapter → Section → Worked Example → Exercise → Question. Chunking that into 500-token blocks and running flat top-k throws away the only reliable signal you have. Instead: the tree is the index, vectors are the ranker. Filter to a taxonomy node in the database first — exact, free, no embeddings involved — then rank semantically inside that subtree of a few hundred candidates.

JobCorpusMethodWhen you build it
Classify a paper questionValidated Question Library — not the textbookHybrid BM25 + dense retrieval, rerank, exemplars into a constrained promptSprint 2. This is the layer that pays for itself.
Suggest practiceNCERT exercises tagged by sub-topic × tierA SQL lookup. Vector search is the fallback, not the defaultSprint 5. ~400 tagged items for Class X Maths.
Explain a conceptNCERT prose and worked examplesPre-filtered ANN inside the subtree, then parent-document expansionLater. Nothing in the pilot report needs it.

Concretely, for this pilot the "vectorise NCERT" job is small: tag roughly 400 exercise questions across 15 chapters with a sub-topic and a tier. That is a structured tagging task, not a document-AI project, and it is the same spreadsheet the reviewers are already filling for the question paper.

The piece worth more than the embeddings

Add prerequisite edges between sub-topics — composite solids requires cone surface area and cylinder surface area. When a student fails a composite-solids question, the useful answer is which gap it is, and only the graph can tell you. Hand-curated once per subject, and it never needs retraining.

Sequencing note

S2 through S5 have a hard dependency you cannot compress: you need real photographed answer scripts before S4 is designable, because handwriting, ink, glare and margin layout at this specific school determine the crop strategy. Get five sample scripts photographed on a teacher's actual phone during S1 — not scanned on a flatbed, which produces images nothing like production.

What I need from you to start

Five things. The first two block Sprint 0 and Sprint 1; the rest block Sprint 2 onward.

  1. Your company logo — SVG preferred, plus a PNG fallback, and the brand colours if you have them. This goes on the landing page, the test and every exported PDF.
  2. Confirmation on Tamil — do the 36 items need Tamil at launch, or is English-only acceptable for the first cohort with Tamil in S6? This changes Sprint 1 by about a day plus translation review.
  3. Two past Class X Maths question papers from this school — ideally one with internal choice, so the choice_group handling is tested against reality rather than my assumption.
  4. Five sample answer scripts, photographed page by page on a teacher's own phone, in the room where scanning will actually happen. This is the single most valuable input you can give me and it determines the entire Sprint 4 design.
  5. How the school records marks today — margin numbers only, a cover-page total, a per-section total, or a tabulated grid. If there is no total anywhere, I will send you a one-page marks strip to print, and the whole extraction problem gets dramatically easier.

Give me 1 and 2 and Sprint 0 starts immediately; the rest can arrive during Sprint 1.
