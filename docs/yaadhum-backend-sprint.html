Read this before you start the clock

The backend is not the critical path. The blueprint is.

The real 3-day risk

The code below runs in three days. The pilot does not go live in three days, because it also needs every question in Unit Test II classified to a sub-topic and a tier, by two independent reviewers — roughly 30 questions × 2 reviewers, plus adjudication. That is a human task of about 2–3 person-days, and it needs zero backend code to begin.

Start it on the morning of Day 1, in a spreadsheet, in parallel. If it starts after the backend is done, you have a six-day project, not a three-day one. Task B3 below expects that spreadsheet to exist by Day 3 morning — the backend just imports it.

Second constraint worth stating plainly: three days buys you the deterministic product — ingest, validate, analyse, report. It does not buy OCR, LLM classification, or psychometrics. That is the right trade: the deterministic layer is the part a teacher will check by hand and the part that must be exactly right, and it is also 100% of what the free pilot output promises.

02

The board

Fifteen tasks. Each has a done-when that is a test, not an opinion.

Day 1Foundation
Goal: a running API with the real schema and the real Class X Maths taxonomy loaded.
B11.0 h

Repo, Compose, config, health

FastAPI skeleton, Postgres 16 container, typed settings, Ruff, pytest wired.

STACK uv · fastapi · compose · ruff
DONE WHEN docker compose up then GET /health → 200 with a live DB ping

B22.5 h

Schema + first migration

Nine tables: school, section, student, taxonomy_node, chapter_weight, assessment, question, question_skill, mark_event. Plus data_quality_flag and analysis_run.

STACK sqlalchemy 2.0 · alembic
DONE WHEN alembic upgrade head and downgrade base both run clean on an empty DB

B32.0 h

Taxonomy + board weights seeder

YAML → DB loader for Class X Maths: 15 chapters, sub-topics, the three CBSE tiers, and the board chapter-weight table with a source URL per row.

STACK pyyaml · sqlalchemy
DONE WHEN seeder is idempotent, and a test asserts board weights sum to 100

B41.5 h

Assessment + Q-matrix API

POST /assessments and bulk POST /assessments/{id}/questions carrying max_marks, sub-topic code, tier code. Codes are FK-resolved, never free text.

STACK fastapi · pydantic v2
DONE WHEN an unknown sub-topic code returns 422 naming the bad row

B51.0 h

Tenancy + auth stub

API key → school_id in request context; a single dependency injects it and every query filters on it. Real OIDC and Postgres RLS come later — the column and the discipline start now.

STACK fastapi depends
DONE WHEN a test reading school B’s assessment with school A’s key returns 404, not 403

SUBTOTAL8.0 h
Day 2Ingest & validate
Goal: marks go in from a CSV, bad data cannot get through, and synthetic data exists for Day 3.
B62.0 h

Append-only mark events + projection

Bulk POST /marks. Every write is an insert with source, actor_id, ts. A view resolves the current value by precedence verified > teacher > ocr.

STACK sqlalchemy core · postgres view
DONE WHEN re-posting a corrected mark keeps both rows and the projection returns the newer one

B71.5 h

Teacher CSV import

Student rows × question columns — the format teachers actually produce. Tolerant parser: blank = not attempted, A = absent, whitespace and stray slashes stripped. Returns a per-cell error list.

STACK pandas · python-multipart
DONE WHEN a file with 2 bad cells imports the other 38 students and returns exactly 2 located errors

B82.5 h

Validation engine

Five rules: per-student sum equals recorded total; mark within range and on a legal step; absent is explicit, never zero; every question classified; paper max_marks sums to the paper total. Failures write data_quality_flag.

STACK pure python · pytest
DONE WHEN each rule has a unit test, and report generation returns 409 while any blocking flag is open for that student

B91.0 h

Statistical anomaly scan

Items everyone got right or wrong; items with negative point-biserial. Advisory flags, not blocking — they route a human to look at a probable marking or entry error.

STACK scipy.stats.pointbiserialr
DONE WHEN a planted mis-keyed item in the fixture raises the flag

B101.0 h

Synthetic fixture generator

40 students, 30 questions, a realistic ability spread and a planted weakness in composite solids so the analyzer has a known right answer to find.

STACK numpy · a seeded RNG
DONE WHEN one command produces a complete, valid assessment end to end

SUBTOTAL8.0 h
Day 3Analyse & report
Goal: three report endpoints returning structured findings, provably correct against hand-computed numbers.
B112.5 h

Deterministic analyzer

Loss by chapter, sub-topic and tier — always with the denominator. The sub-topic × tier cross-tab. Class aggregates and the commonly-missed ranking. Wilson intervals on every rate, and the evidence floor: under 2 marks or 2 questions returns insufficient_evidence, never a percentage.

STACK pandas · scipy · raw SQL
DONE WHEN a golden-file test matches numbers computed by hand for one fixture student

B121.0 h

Board-weighted indicator

The scope formula, plus a credible interval and normalised share of total indicator mass. Chapters with zero marks in the paper emit a coverage_gap finding.

STACK scipy.stats.beta
DONE WHEN a chapter with 0 marks and 12% board weight produces a coverage_gap, not a 0.0

B131.5 h

Paper quality report

Per-item difficulty and point-biserial, Cronbach’s α, and observed-vs-target typology mix (54 / 24 / 22) by χ² plus a 0–1 alignment score.

STACK scipy.stats · pandas
DONE WHEN α and χ² match a reference computation on the fixture to 4 dp

B142.0 h

Three report endpoints

GET /reports/student/{id}, /reports/class/{section_id}, /reports/paper/{assessment_id} — all reading one findings table, ranked by board_weight × evidence × actionability, capped at 5. Same numbers, three projections.

STACK fastapi · pydantic response models
DONE WHEN a contract test pins the response schema and the cap holds

B151.0 h

End-to-end test + handover

One pytest: seed → import CSV → validate → analyse → fetch all three reports. Plus a README with the four commands and the live OpenAPI page.

STACK pytest · httpx · OpenAPI
DONE WHEN the single test is green from an empty database

SUBTOTAL8.0 h

If you have two developers

Don’t split by day — split by dependency. Dev A takes the vertical: B1 → B2 → B4 → B5 → B6 → B7 → B14. Dev B starts with B10 on hour one (write the fixture generator against the schema in B2 as soon as it lands), then B8 → B9 → B11 → B12 → B13. They meet at B14. This finishes in roughly two days rather than 1.5, because B10-first lets Dev B build and test the entire analyzer without waiting for the ingestion path to exist.

03

Explicitly cut — and when it returns

Say these out loud to whoever is expecting a demo, before Day 1, not after Day 3.

CutWhy it doesn’t fit in 3 daysReturns
OCR pipelineNeeds annotated scripts, a trained recogniser and a review UI — a two-week project on its ownv1. Use a pre-printed marks strip or teacher entry for the pilot
LLM classificationNeeds the validated library and a calibration set that don’t exist yetOnce ~200 adjudicated questions exist
G-DINA / IRTModel fitting plus identifiability work; the deterministic layer must be trusted firstv1, after cycle 2 data lands
Bandit / RLNeeds multi-cycle logged outcomes; there are nonev2, at ~10 schools
dbt, ClickHouse, Temporal, MLflowEach is a service to operate; one school does not generate the load that justifies any of themWhen school #3 signs
FrontendNot backend scope. The OpenAPI page is the Day-3 demo surfaceParallel track, separate estimate
Postgres RLS, OIDCThe school_id column and the filter discipline land now; the enforcement layer is a day on its ownBefore school #2
One thing not to cut

Keep mark_event append-only even though a mutable marks table would save you about ninety minutes on Day 2. That ninety minutes is the difference between having an audit trail, OCR-vs-teacher reconciliation and correction history for free later, versus a painful migration once real school data is in the table.

04

What Day 4 looks like

So the sprint ends pointing somewhere.

  • Import the real blueprint from the reviewers’ spreadsheet (the parallel track from section 00) and re-run the analyzer against real Unit Test II questions instead of the fixture.
  • First real marks for one section, entered by one teacher, watched by you. Every friction point in that hour is worth more than a week of design.
  • Render one student report as a PDF and put it in front of a teacher with one question: “would this change what you teach on Monday?”
  • Measure inter-reviewer κ on the blueprint you just imported. If it’s under 0.7 on sub-topic, the taxonomy is ambiguous — fix the taxonomy, not the model.
